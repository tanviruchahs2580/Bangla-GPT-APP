## 1. Executive summary

This pass audited `main` at `1bf0625` — the state the previous audit merged — rather than
trusting its conclusions. Three independent deep audits ran in parallel (backend, frontend,
CI/docs), every claim was reproduced before it was acted on, and each fix carries a test where
a test can express the property.

The three findings that mattered:

- **The dependency-update pipeline could not land anything, and the gate that was supposed to
  catch it was a tautology.** `Lockfile is in sync with pyproject.toml` ran
  `pip-compile --output-file constraints.txt` *inside the checkout* — overwriting the committed
  lock — and then read that regenerated file back to assert each dependency in `pyproject.toml`
  appeared in it. That is true of any file compiled from `pyproject.toml`. The concrete miss:
  Dependabot pinned `redis==8.1.0` while `arq` requires `redis[hiredis]<6`; the guardrails job
  passed in 32 s and five other jobs then died with `ResolutionImpossible`. Security updates
  were therefore not landing. The Bangla-script step had the same shape (`|| true` on a scanner
  that always exits 0).
- **The API was published on a random host port bound to `0.0.0.0`.** `docker-compose.yml`
  claimed the port was published "ONLY when `API_HOST_PORT` is set" and that unsetting it kept
  traffic behind the proxy. Compose renders an empty host segment as a full port entry.
  Reproduced against the daemon: `published: 54390`, `URL: 0.0.0.0`.
- **Six user-visible defects that showed users untrue things**, the clearest being that every
  API timestamp was parsed as local time — the backend serialises naive UTC with no offset and
  `new Date()` reads an offset-less string as local, so deadlines displayed six hours early in
  Dhaka.

## 2. Scope, environment and method

**Environment.** Windows 10.0.26300 (x64), Git Bash, Python 3.12.10, Node v24.19.0, npm 11.17.0,
Docker Compose v5.4.0, gh authenticated as `tanviruchahs2580`.

**Method.** Repository discovery (identity, branch, remote, status) → baseline (full test suites,
lint, type-check, build, `pip-audit`) → three parallel read-only audits with an explicit
instruction to report only reproducible defects with `file:line` and a concrete failure scenario →
independent reproduction of every finding before acting on it → focused fixes with tests →
full re-validation → commit, push, and this branch's own CI as the release gate.

**Baseline at `1bf0625`, before any change.** API 1026 passed / 6 skipped; web 62 files /
226 tests passed; `tsc`, `eslint --max-warnings 0`, `prettier --check`, `ruff check`,
`ruff format --check`, `mypy src` and `npm run build` all clean; `pip-audit` reports no known
vulnerabilities in the pinned set. The defects below are therefore not "the tests were red".

## 3. Fixed, with the evidence that found it

### 3.1 CI and release defects (S1)

| # | Defect | Fix |
|---|---|---|
| C-1 | The lockfile guard overwrote the file it graded, then graded its own output — a tautology. `CONTRIBUTING.md` promised a stale lock could not slip through. | `apps/api/scripts/check_lockfile.py`: read-only, offline, asserts that every declared dependency is pinned and that the pin satisfies the declared specifier. 10 regression tests, including the exact Dependabot bump and a byte-for-byte assertion that it does not rewrite the lock. |
| C-2 | `redis>=5.0` was an over-broad declaration: `arq` (0.28.0, the newest release) caps `redis[hiredis]<6`, so no redis 6/7/8 can install. Dependabot proposed one anyway. | `pyproject.toml` declares `redis>=5.0,<6` with the reason and the command to re-check it; `dependabot.yml` ignores redis majors ≥ 6 that cannot coexist with arq, while still allowing 5.x security patches. |
| C-3 | The Bangla-script step ended its scanner call with `|| true`, and `bn_scan.py` always exits 0 — so "the tool ran and found nothing" and "the tool never ran" produced the same green step. | Exit status left intact, plus an empty-output assertion. |
| C-4 | The doc-path guard's extension list stopped at `.md`/`.ts`/`.css`/`.example` while the step is named "Every repo path a document names exists", and it scanned untracked files (green in CI, red locally). | Classes spelled out; dot-directories skipped. Coverage 64 → 74 paths, all of which exist. |
| C-5 | The release workflow's post-deploy gate curled `127.0.0.1:8000/health`, which cannot answer when the operator follows the docs and leaves `API_HOST_PORT` unset — so it failed **healthy** releases. | Gate reads the api container's own healthcheck, which does not depend on the host mapping. |
| C-6 | The runbook, README and hosting notes all promised a health-gated rollback. The rollback sat inside the `compose up` branch only, so a release that started and then failed its health gate was never rolled back. The documented manual rollback also omitted the image tags, so `docker compose pull` looked for a `:local` tag that does not exist and the `&&` chain stopped. | Both failure paths roll back through one function; the runbook's rollback command includes `API_TAG`/`WEB_TAG`. |

`bash -n` on the extracted deploy script, `docker compose config` on every profile, and YAML
validity of all six changed config files were each checked before push.

### 3.2 Security posture (S1)

| # | Defect | Fix |
|---|---|---|
| S-1 | `ports: - "${API_HOST_PORT:-}:8000"` with a comment saying the API is published "ONLY when `API_HOST_PORT` is set". An unset variable renders as a full port entry, so the API was published on a **random host port bound to 0.0.0.0** — the opposite of the posture four documents describe, and a deployed API had ended up listening on every interface that way. | Deterministic and loopback-only by default (`127.0.0.1:8000`), with `API_HOST_BIND` as the deliberate opt-in. `docker compose config` verified for all three variable combinations. Caddy and nginx never used the mapping — they reach `api:8000` over the Compose network. |

### 3.3 API correctness (S2/S3)

| # | Defect | Fix |
|---|---|---|
| A-1 | `AssignmentIn.num_questions` allowed 25 while `QuizSubmitRequest.answers` allowed 20 items. A 21-question assignment was rejected with 422 before the handler ran, the attempt stayed open forever, and nothing deletes an assignment. | Both bounds come from one `MAX_QUIZ_QUESTIONS`. The regression test walks every count from 1 to the ceiling rather than reading pydantic metadata. |
| A-2 | `subject`/`chapter` were unbounded on the ask, chat and quiz routes but are written to `VARCHAR(60)`/`VARCHAR(200)` columns — a 500 on PostgreSQL, not a 422 — and are interpolated into the provider prompt. | Bounded to the column widths. |
| A-3 | `send_verification_email` inserted a new 24-hour code and stopped there. Every `/auth/resend-verification` left the previous code alive, so a code seen earlier kept working after the user asked for a new one: resend invalidated nothing. | Pending codes are burned first, the way `forgot_password` already did for reset tokens. 3 regression tests. |
| A-4 | `learning_prefs.subject_focus` could be set but never cleared — the route merges the dict, so omitting the key kept the old value and the school reported a save that had not happened. | An explicit `null` removes the key; `""` stays invalid so the whitelist keeps one meaning. |
| A-5 | `/school/analytics` derived its day bound from a UTC instant while `DailyActivity.date` holds Asia/Dhaka calendar days, so a 7-day window admitted up to 9 days of rows and diluted `daily_active_avg`. | `dhaka_date(since)`, the helper every other reader of that column uses. |

### 3.4 Web defects (S2/S3)

| # | Defect | Fix |
|---|---|---|
| W-1 | `friendlyError()` was handed a bare machine code on the register, verify and reset paths, but its string branch consulted only the legacy Bengali table — so `rate_limited` and `invalid_token` fell through to "something went wrong" while the same code inside an object produced the right copy. | The function accepts either shape, which fixes every caller at once. | W-2 | Offset-less API timestamps were parsed as local time. | W-4 | The student's preference save rendered its error in the success class (green), under a message that said "saved". | Success and failure are distinguished. |
| W-5 | Class-health labels were built at module load, so they kept the language active on first import until a hard reload. | Keys evaluated at render. |
| W-6 | Switching the report period unmounted the report card *and the control just used*. | `placeholderData` keeps the previous period on screen while the next loads. |
| W-7 | Destructive actions had no confirmation: the admin retention purge (one click, permanent, server-side) and teacher document delete, which also swallowed its errors. | Two-step confirm on both, matching account deletion; failures are shown. |

| W-10 | `check_i18n.py` read the `en` dictionary as everything from `const en` to the end of the file, so any object added below it was parsed as translations. | The block ends where the literal does. |

## 4. Attempted, then reverted

`FeedbackRequest.rating = 0` was flagged as a data-quality defect and tightened to
`Literal[-1, 1]`. That broke `test_feedback_without_target_is_400_not_422`, which documents
`{"rating": 0}` as **deliberately** schema-valid: `rating` is a required field, so 0 is the only
way to send a comment with no thumbs answer, and an aggregate counting only -1/+1 is then
correct rather than incomplete. The only client sends `1 | -1` (verified). The change removed a
capability instead of fixing one, so it was reverted and the misleading `# -1 or +1` model
comment — the actual inconsistency — was corrected instead. The revert was caught by the full
local suite, which is the reason that suite is run before pushing.

## 6. Found, reproduced, deliberately not fixed

- **`/assignments/mine` windows platform-wide before filtering by membership.** Membership lives
  in the `attempts` JSON, so the candidate set is the newest `limit` assignments *on the whole
  platform*; on a deployment with more than that many newer assignments, a student's older
  assignment is not returned and they have no way to open it. A correct fix needs an indexable
  membership column with its own migration. A school-scoped stopgap was considered and rejected:
  `User.school_id` is nullable while tenancy resolves school-less staff to the default school,
  so a naive filter could hide legitimate work — a worse bug than the one it fixes.
- **Check-then-insert races on unique-keyed rows** (daily activity, chapter progress, revision
  queue, adaptive practice, concept mastery, classroom import) are unhandled in several places.
  In the quiz and chat paths the write is committed *before* the activity record, so a losing
  race answers 500 after the business write has already landed. Needs per-site `IntegrityError`
  handling; too broad to fold into this pass.
- **MFA step-up and email-verification tokens bypass the token-epoch revocation** that a password
  change performs, so a step-up token held by an attacker still completes after the victim resets
  their password. Requires a TOTP code, so it is a revocation failure rather than an MFA bypass.
- **Frontend:** a new chat started mid-stream can mix tokens across conversations; the evidence
  modal's focus effect re-runs on every streamed token (inline `onClose` in its dependency
  array); switching language remounts the tree and discards in-progress state (a half-written
  question, an open conversation).
- **Unbounded admin reads**: `/assignments/mine` accepts `limit` up to 500 and the admin user list
  scans without a covering index for the free-text search.

None of these are hidden by a passing test or a weakened check — each is stated here with the
reason it was left, and the first two are the ones to schedule next.

## 7. What was not verified

- No live deployment: this pass changed the compose host-port default, which the live host may
  rely on (`API_HOST_BIND` is the documented opt-in, and a same-host tunnel reaching
  `127.0.0.1:8000` keeps working). The owner should confirm the deployed `.env` before the next
  release recreate.
- No browser session: the frontend findings were reproduced by reading code and state flow, and
  covered by unit tests, but no rendered-page or screen-reader check was run in this pass.
- The release workflow's new rollback path was syntax-checked but not executed — it runs only on
  a `v*.*.*` tag with `DEPLOY_ENABLED=true` and host secrets.
- `arq`'s redis ceiling was read from the installed metadata and from PyPI; it is correct as of
  arq 0.28.0, and the `dependabot.yml` ignore carries the command to re-check it.
- Firefox, WebKit, mobile APK and any flow needing a real model-provider key remain unverified,
  as in the previous pass.
