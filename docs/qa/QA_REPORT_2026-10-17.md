## 1. Executive summary

This pass audited `main` at `1bf0625` — the state the previous audit merged — rather than
trusting its conclusions. Three independent deep audits ran in parallel (backend, frontend,
CI/docs), every claim was reproduced before it was acted on, and each fix carries a test where
a test can express the property.

The three findings that mattered:

- **The dependency-update pipeline could not land anything, and the gate that was supposed to
  catch it was a tautology.** `Lockfile is in sync with pyproject.toml` ran
  `pip-compile --output-file constraints.txt` *inside the checkout* — overwriting the committed
  lock — and then read that regenerated file back to assert each dependency in `pyproject.toml`
  appeared in it. That is true of any file compiled from `pyproject.toml`. The concrete miss:
  Dependabot pinned `redis==8.1.0` while `arq` requires `redis[hiredis]<6`; the guardrails job
  passed in 32 s and five other jobs then died with `ResolutionImpossible`. Security updates
  were therefore not landing. The Bangla-script step had the same shape (`|| true` on a scanner
  that always exits 0).
- **The API was published on a random host port bound to `0.0.0.0`.** `docker-compose.yml`
  claimed the port was published "ONLY when `API_HOST_PORT` is set" and that unsetting it kept
  traffic behind the proxy. Compose renders an empty host segment as a full port entry.
  Reproduced against the daemon: `published: 54390`, `URL: 0.0.0.0`.
- **Six user-visible defects that showed users untrue things**, the clearest being that every
  API timestamp was parsed as local time — the backend serialises naive UTC with no offset and
  `new Date()` reads an offset-less string as local, so deadlines displayed six hours early in
  Dhaka.

## 4. Attempted, then reverted

`FeedbackRequest.rating = 0` was flagged as a data-quality defect and tightened to
`Literal[-1, 1]`. That broke `test_feedback_without_target_is_400_not_422`, which documents
`{"rating": 0}` as **deliberately** schema-valid: `rating` is a required field, so 0 is the only
way to send a comment with no thumbs answer, and an aggregate counting only -1/+1 is then
correct rather than incomplete. The only client sends `1 | -1` (verified). The change removed a
capability instead of fixing one, so it was reverted and the misleading `# -1 or +1` model
comment — the actual inconsistency — was corrected instead. The revert was caught by the full
local suite, which is the reason that suite is run before pushing.

## 6. Found, reproduced, deliberately not fixed

- **`/assignments/mine` windows platform-wide before filtering by membership.** Membership lives
  in the `attempts` JSON, so the candidate set is the newest `limit` assignments *on the whole
  platform*; on a deployment with more than that many newer assignments, a student's older
  assignment is not returned and they have no way to open it. A correct fix needs an indexable
  membership column with its own migration. A school-scoped stopgap was considered and rejected:
  `User.school_id` is nullable while tenancy resolves school-less staff to the default school,
  so a naive filter could hide legitimate work — a worse bug than the one it fixes.
- **Check-then-insert races on unique-keyed rows** (daily activity, chapter progress, revision
  queue, adaptive practice, concept mastery, classroom import) are unhandled in several places.
  In the quiz and chat paths the write is committed *before* the activity record, so a losing
  race answers 500 after the business write has already landed. Needs per-site `IntegrityError`
  handling; too broad to fold into this pass.
- **MFA step-up and email-verification tokens bypass the token-epoch revocation** that a password
  change performs, so a step-up token held by an attacker still completes after the victim resets
  their password. Requires a TOTP code, so it is a revocation failure rather than an MFA bypass.
- **Frontend:** a new chat started mid-stream can mix tokens across conversations; the evidence
  modal's focus effect re-runs on every streamed token (inline `onClose` in its dependency
  array); switching language remounts the tree and discards in-progress state (a half-written
  question, an open conversation).
- **Unbounded admin reads**: `/assignments/mine` accepts `limit` up to 500 and the admin user list
  scans without a covering index for the free-text search.

None of these are hidden by a passing test or a weakened check — each is stated here with the
reason it was left, and the first two are the ones to schedule next.

**The one decision that mattered.** The tunnel targets `host.docker.internal:8000`, and from
inside a bridge-network container the host is the Docker gateway, not `127.0.0.1`. The new
loopback default (§3.2) would therefore have cut the public API off at the next recreate. The
tunnel also cannot be recreated to fix that: it is a quick tunnel, so restarting it issues a new
random hostname and breaks the origin baked into Vercel — the failure that already took
production down twice (`deploy/DEPLOYMENT.md`). So the binding was widened **deliberately and
with the reason written into the env file**:

```
API_HOST_BIND=0.0.0.0   # the containerised quick tunnel cannot reach loopback
```

which renders exactly the `0.0.0.0:8000` the container already had, verified with
`docker compose config` before the change. Narrowing this (or moving the tunnel onto the compose
network so it can use `api:8000`) is the right follow-up, and it needs the tunnel to be made
stable first — that is an owner decision, not something to do during a deploy.

১. **ডিপেন্ডেন্সি আপডেট আর জমত না।** লকফাইল যাচাইয়ের ধাপটি নিজেই লকফাইলটি মুছে নতুন করে বানিয়ে

ঢুকে পড়ে পাঁচটি CI জব ব্যর্থ হয় এবং নিরাপত্তা আপডেট আটকে থাকে। এখন যাচাইটি পড়া-মাত্র, ইন্টারনেট
ছাড়াই চলে, এবং ভুলটি ধরা পড়ে।

২. **API সব ইন্টারফেসে একটি র‍্যান্ডম পোর্টে খোলা ছিল।** কনফিগারেশনে লেখা ছিল পোর্ট কেবল
`API_HOST_PORT` দিলেই প্রকাশ পাবে — কিন্তু না দিলে Compose এটিকে র‍্যান্ডম পোর্টে `0.0.0.0`-তে
প্রকাশ করে। এখন ডিফল্ট কেবল লুপব্যাক, প্রশস্ত করতে হলে সচেতনভাবে `API_HOST_BIND` দিতে হবে।

৩. **ব্যবহারকারীকে ছয় জায়গায় ভুল তথ্য দেখানো হচ্ছিল।** সবচেয়ে বড়টি: সার্ভার সময় UTC-তে টাইমজোন
ছাড়া পাঠায়, আর ব্রাউজার সেটিকে স্থানীয় সময় ধরে — তাই ঢাকায় প্রতিটি ডেডলাইন ছয় ঘণ্টা ভুল দেখাত।
এছাড়া ইন্টারনেট সমস্যায় "শিক্ষকের দেওয়া কোনো কাজ নেই" দেখানো, ভুল বার্তায় সবুজ "সংরক্ষিত" দেখানো,
আর বিষয়-ফোকাস একবার দিলে মুছবার উপায় না থাকা — সব ঠিক করা হয়েছে।

বাকি যা এখনো বাকি (যেমন `/assignments/mine`-এ পুরো প্লাটফর্ম স্ক্যান, কিছু রেস কন্ডিশন) তা §6-এ
কারণসহ লেখা আছে — ঢেকে রাখা হয়নি।

**ডিপ্লয় সম্পন্ন (২০২৬-১০-১৭)।** আপনার নির্দেশে কোডটি `main`-এ মার্জ করা হয়েছে (`2f861a7`) এবং
লাইভে ডিপ্লয় করা হয়েছে — সব দশটি চেক সবুজ ছিল। ওয়েব (Vercel) ও API (নতুন ইমেজ, ডেটাবেস ব্যাকআপ
নেওয়ার পর মাইগ্রেশন ও `alembic check` পরিষ্কার) দুটোই আপডেট হয়েছে, এবং লাইভে যাচাই করা হয়েছে:
ব্যবহারকারী-স্তরের ১৩টি চেক পাস, আর এই শাখার নিজের সংশোধনগুলোর ৯টি চেক পাস। তবে একটি গুরুত্বপূর্ণ
সিদ্ধান্ত নিতে হয়েছে: পাবলিক টানেলটি একটি কন্টেইনারে চলে এবং `host.docker.internal` দিয়ে API-তে
পৌঁছায়, তাই নতুন লুপব্যাক-ডিফল্ট রাখলে পাবলিক API বন্ধ হয়ে যেত। তাই ডিপ্লয়মেন্টের env ফাইলে কারণ
লিখে `API_HOST_BIND=0.0.0.0` দেওয়া হয়েছে — এটিই আগের অবস্থা, এখন সচেতন ও নথিবদ্ধ। টানেল
স্থিতিশীল (নামযুক্ত) না হওয়া পর্যন্ত এটি সংকুচিত করা যাবে না। এছাড়া `LLM_PROVIDER=mock`,
`ENV=test`, SMTP বন্ধ — এগুলো আপনার সিদ্ধান্ত, ডিপ্লয়ের সময় বদলানো হয়নি।
