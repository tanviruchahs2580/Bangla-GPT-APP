## 9. Security and privacy

Reviewed against OWASP ASVS 4.0.3 Level 2 as a baseline, OWASP Top 10 2021, OWASP API Security
Top 10 2023 and OWASP Top 10 for LLM Applications 2025; no claim of certification or full
compliance is made. Evidence: `.qa-work/audit/security-review.md`, and the probe outputs it
cites.

- **Two-school isolation was proven** for every endpoint probed: cross-tenant reads and writes
  answer 403 with a stable code, object-id substitution answers 403/404, and the one exception
  found (S-007, the shared chapter-content library) is fixed and now covered by a test.
- **Authentication:** Argon2id with the parameters named in `auth/security.py`; JWT algorithm
  pinned, `exp`/`iat` validated, revocation by token epoch on password change; reset tokens are
  hashed at rest, single-use, expiring, and now invalidated by a password change; login is
  rate-limited by IP **and** by account after this run.
- **Production guards verified by booting the app:** it refuses to start with a default or
  placeholder JWT secret, the mock LLM provider, a missing or malformed PII key, wildcard CORS,
  in-memory rate limiting with multiple workers, SQLite with multiple workers, public
  `/metrics`, or without SMTP configuration. There is no debug flag to leak.
- **Secrets:** gitleaks over the tree and the full history finds no credential. One historical
  hit is a reviewed false positive (ASCII-art text in an archived report) and is allowlisted by
  matched text. `docs/archive/` still publishes demo account passwords from 2026-09; an
  archived report records that they were rotated and no longer work, and no seeding path in
  the repository recreates them — the owner should confirm the accounts are gone (§12).
- **Residual risks, stated plainly:** a locked account answers 429 while an unknown email
  answers 401, so an attacker who already knows an address can learn that it exists and is
  locked (inherent to account lockout; the per-IP limit bounds the attempt rate);
  `TRUST_PROXY_HEADERS` must be set correctly by the operator, and the deployment docs now say
  how; there is no refresh-token flow, so a stolen 60-minute token cannot be revoked except by
  a password change; EXIF stripping needs an image library and is not implemented (the
  provider receives the original bytes of an accepted image).
- **Privacy:** the export now covers every per-user table; deletion cascades completely (proven
  by counting rows to zero and confirming the account can no longer authenticate); logs redact
  exception tracebacks as of this run; the government aggregate export's small-cell suppression
  was read but not exercised end-to-end.
