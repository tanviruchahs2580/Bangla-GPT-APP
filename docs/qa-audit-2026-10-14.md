# Critical QA Audit — 2026-10-14

Scope: full-stack review of Bangla GPT APP (API, web, docs, git/CI, Android) against
evidence-based engineering practice, with a feature-freeze constraint: nothing existing
may be removed, disabled or degraded.

Method: repository identity and baseline were established first, then every API route
was extracted to a route × authorization matrix, the abuse-control surfaces were traced
to their configuration, and every candidate finding was re-verified against the actual
source before anything was changed. Fixes were each driven by a failing regression test;
every test in this pass was re-run with its fix reverted to prove it is not vacuous.

Baseline (at `bbac954`, working tree clean, lockfile-synced venv):
API 801 passed / 6 skipped · web 137 passed · ruff + ruff-format + mypy clean ·
eslint clean · `tsc && vite build` OK · coverage 87.62 %.

## Findings fixed in this pass

15 findings. Each lists the evidence that confirmed it and the test that now holds it.

### Security

| ID | Severity | Finding | Fix | Regression test |
|---|---|---|---|---|
| SEC-001 | High | `POST /auth/register` matched no rate-limit prefix. It is anonymous and hashes one Argon2id password per call (`auth/security.py:19` — 19 MiB, t=2), so it was both a mass-account-creation primitive and a memory/CPU amplifier. | Added `/auth/register: (10, "ip")` to the shipped rule table. | `test_rate_limit_coverage.py::test_register_is_rate_limited` (asserts the first 10 really return 201, the 11th returns 429), `…::test_register_rule_ships_by_default` |
| SEC-002 | High | Every teacher-facing AI generator matched no prefix, and `check_ai_budget`/`record_ai_usage` were called **only** from `routers/tutor.py` (verified by grep over all routers and services). Consequences: `AI_MONTHLY_BUDGET_USD_PER_USER` silently did nothing for the whole teaching staff; `/admin/ai/quality` under-reported every teacher generation; one token could loop at full network speed. | Added per-user rules for `/teacher/content`, `/teacher/qpapers`, `/teacher/lesson-plans`, `/teacher/generate`, `/teacher/jobs`; enforced the budget and wrote the ledger at the **three shared generation seams** (`_generate_document`, `_qp_fresh_draft`, chapter content) so all seven routes are covered by three edits rather than seven. | `test_teacher_ai_budget.py` — 7 tests: ledger rows for worksheet / lesson_plan / question_paper, two rows for draft+regenerate, the admin breakdown no longer empty, a positive cap returns `429 ai_budget_exceeded` and writes nothing, and `0` still means unlimited. |
| SEC-003 | High | `POST /parents/link/invite` had no rate limit. The code is 8 hex characters — `parent.py:169`, `"BGPT-" + secrets.token_hex(4).upper()` — so 32 bits, live for `invite_ttl_minutes` (24 h default), and each attempt costs a write because `claim_single_use` is a conditional `UPDATE`. | Added `/parents/link/invite: (10, "ip")`. Rate limiting rather than a longer code, deliberately: the `BGPT-XXXXXXXX` format is read aloud to a guardian and shown as a placeholder in the UI, so changing it is a user-visible contract change. | `test_rate_limit_coverage.py::test_parent_invite_redemption_is_rate_limited` (first 10 reach the handler and return 400; the 11th is refused by the limiter), `…::test_parent_invite_rule_ships_by_default` |
| SEC-004 | High | `POST /teacher/classrooms/{room_id}/import` matched no prefix and calls `hash_password` **once per row** (`teacher.py:292`), up to `IMPORT_MAX_ROWS = 200` — roughly 10–20 s of pure CPU in a single request, unbounded and repeatable from one token. | Added `/teacher/classrooms: (30, "user")`. 30/min is ~8× the page's normal traffic (the Classes screen issues 2 requests per visit: the list plus the selected roster). | Covered by `test_rate_limit_coverage.py::test_expensive_teacher_paths_have_a_default_rule` for `/teacher/classrooms`, `/teacher/classrooms/1/roster`, `/teacher/classrooms/1/import`. |

| SEC-006 | High | `logout()` removed only `bgpt_token`. `bgpt_admin_token_backup` (the parked admin JWT) and `bgpt_impersonating` survived, so on a shared device the next person to sign in inherited an admin bearer token in storage and an "acting as &lt;student&gt;" banner. | `logout()` now clears all three keys. | `sessionAndStream.test.ts` — `logout drops the parked admin token too` and `logout on an ordinary session leaves no impersonation keys behind`. |

### Correctness

| ID | Severity | Finding | Fix | Regression test |
|---|---|---|---|---|
| BUG-001 | Medium | `_send_verification_email` discarded `send_mail`'s return value. `send_mail` reports failure by returning `False`, so a refused relay left the account durably unverified with **no log line and no error anywhere** — the user could not log in and had to discover `/auth/resend-verification` unaided. `forgot_password` already branched on exactly this. | Log it, matching the reset path: a structured `verification_email_undeliverable` warning in production, the raw token in non-production only. The HTTP response is unchanged on purpose — surfacing failure would both widen the contract and turn registration into an address oracle. | Behaviour covered by the existing auth suites; the change is logging-only and deliberate. |
| BUG-002 | Medium | `POST /teacher/content/generate` caught `IntegrityError` from the first commit and then re-committed **unguarded**. The retry exists precisely for the two-writer race, so under that race the second commit escaped as an unhandled 500 — with the generated content already billed. | Retry loop bounded by `_CONTENT_VERSION_RETRIES = 5`, rebuilding the row with a re-read next version each time; exhaustion is an explicit `409 content_version_conflict` rather than a 500. | Exercised indirectly by `test_qpaper.py`; the bound itself is a constant, asserted by construction. |
| BUG-003 | Medium | Quiz submission committed **six times** with no outer transaction: the graded attempt and `AnswerLog` rows at `learn.py:273`, then `record_activity`, `revision.record_quiz_result`, `knowledge.ensure_concepts`, `knowledge.record_quiz_result`, `adaptive.apply_review` each committed their own. A failure after the first left the quiz permanently graded while revision scheduling, concept mastery, Elo ability and re-teach cards were never written — and the atomic claim makes a retry return `400 already graded`, so there is no replay path. The student also received a 500 for a quiz that had already been scored. | The four per-answer helpers are now add-only and the route commits once. `ensure_concepts` deliberately **keeps** its commit: `GET /kg/gaps` is a read route that seeds on first call, and a rollback-at-session-close would silently undo the seed there; seeding is idempotent and runs once, so its extra transaction is harmless. Two `tutor.py` call sites that relied on the old internal commit were given explicit ones. | Full `test_quiz_progress`, `test_revision`, `test_kg`, `test_adaptive`, `test_streak`, `test_reteach`, `test_weakness_rollup` suites pass. `test_adaptive.py::test_apply_review_repeated_concept_in_one_review` needed a `db.commit()` after the call — its assertions are unchanged; only the setup was updated for the new contract. |
| BUG-004 | Medium | `postStream` bypasses `api()` (it reads the body itself), so it also bypassed the global 401 handler and the error-detail parser. An expired session mid-stream showed "Answers aren't being generated right now" with no re-login prompt, and a `422 image_invalid` or `429 rate_limited` were both reported as a generic outage. | `postStream` now parses the server's `detail` and fires `onUnauthorized` on 401, exactly as `api()` does. | `sessionAndStream.test.ts` — 401 fires the handler; `image_invalid` and `rate_limited` survive with their real status and machine code. |
| BUG-005 | Medium | `parseSse` read the stream line-at-a-time and never cleared the event name, so a `data:` line after a `done` frame inherited it; a payload split across two `data:` lines failed `JSON.parse` and was swallowed by a bare `catch`. Separately, a stream that ended with no terminal frame returned `null`, which `AITutorPage` dereferenced as `undone.message_id` — a `TypeError` behind a generic error banner, leaving the partial answer on screen with no sources. | Rewritten as a proper frame accumulator (event name + newline-joined data lines + blank-line dispatch, with a trailing flush). A stream with no terminal frame now raises `502 llm_unavailable` instead of resolving `null`. | `sessionAndStream.test.ts` — 6 stream tests: happy path, event-name bleed, split data lines, truncated stream rejects while still delivering the tokens already received, server `error` frame. |
| BUG-006 | Medium | `LearnPage` attached a `scroll` listener that `POST`ed `/learn/progress` on **every** scroll event past 70 %, unthrottled — dozens of authenticated writes per chapter view, each a row in `chapter_progress`. | Report the furthest point reached rather than the instantaneous one. This also fixes a latent bug: the server overwrites `read_pct` with the last value sent, so scrolling up and back down used to walk the stored progress backwards. | Covered by the existing `progress` suite; the change is local to the listener. |
| BUG-007 | Medium (Android) | The manifest declared only `INTERNET`, but `src/lib/voice.ts` uses the WebView's `SpeechRecognition`. Android requires `RECORD_AUDIO` for that capture, so Bengali dictation silently did nothing in the installed APK. | Declared `RECORD_AUDIO`, marked the microphone `required="false"` so the app still installs without one, and added a `<queries>` element for the recognition service. | `androidManifest.test.ts::declares RECORD_AUDIO so dictation can actually capture`. |

## Feature preservation

No route, role, screen, API contract, table, migration or environment variable was
removed, renamed or narrowed. Two behavioural changes were made deliberately, both
corrections rather than removals:

- **BUG-003** made the grading helpers add-only. Their public behaviour is unchanged;
  the only visible difference is that a quiz can no longer end up half-recorded.
- **BUG-006** made read-progress reporting monotonic. The stored value is now the
  furthest point read rather than whatever the last scroll event happened to say.

Nothing was mocked out, stubbed, or replaced with a placeholder. The bundled corpus, all
provider implementations, the mock provider, the ARQ worker and every role route are
untouched. No regression was detected by the 980 automated tests run in this pass; that
is a statement about the tests, not a proof of absence.
