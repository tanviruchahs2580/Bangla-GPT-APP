## P0

### F-1 · `grounded` could not be false for any generated text

`apps/api/src/bangla_gpt_api/services/tutor.py:447` (pre-fix)

```python
citation_ok = verify_citation(answer, " ".join(h.chunk.text for h in hits))
return AskResponse(
    answer=answer,
    grounded=not refused,          # ← the only gate
    sources=[] if refused else refs,
    citation_verified=None if refused else citation_ok,   # ← stored, never read
```

`refused` was a single substring test for one Bengali phrase. A provider that
invented text unrelated to the evidence returned `grounded=True`, three real
textbook citations, and ~0.84 confidence. `verify_citation` was computed, put on
the response field, and read by no consumer — not the route, not the frontend
(`apps/web/src/types.ts` declares the field; nothing rendered it).

**Impact:** a fabricated answer shipped to a student presented as textbook-backed.
This is the core product claim.

**Fix:** `TutorService._finalize()` now settles the state once, and both the
buffered and streaming paths call it. It handles empty output (`provider_empty`),
refusal phrasing (`model_refused`), and citation failure
(`citation_unverified`). On any of those the citations are dropped rather than
shown next to text they do not support, and `grounded` is false.

`verify_citation` gained a minimum-term guard (`_MIN_CITATION_TERMS = 5`): a
two-word reply cannot be judged by a coverage ratio, and the previous behaviour
condemned it on a single missed word.

**Verified:** `tests/test_grounding_honesty.py` (19 tests) and
`apps/web/src/test/tutorGrounding.test.tsx` (3 tests).

## P1

### F-2 · Prompt injection through the quiz-explain field

`services/tutor.py:360` (pre-fix) called the instruction "trusted app text". It
is assembled from `payload.explain.question`, which is client-supplied. A quiz
question containing `</evidence>` closed the evidence block early and injected
text into the highest-authority region of the user message; the resulting prompt
had one more `</evidence>` than `<evidence>` and an unescaped `<user_question>`.

The comment was also false, which is why the gap survived review.

**Fix:** `extra_instruction` passes through the same `sanitize_evidence()` used
for chunks and history; the comment now states where the text comes from.
**Verified:** `test_quiz_explain_instruction_cannot_break_out_of_evidence`.

### F-3 · Mid-stream provider failure left truncated text on screen

`services/tutor.py` reset its local `chunks` list, but the tokens had already
been yielded and the browser had concatenated them. The student read the
truncated primary output followed by the fallback restart.

**Fix:** an explicit `reset` SSE event (`StreamEvent(type="reset")`) is emitted
before the fallback restarts, and the client clears both its accumulator and the
rendered bubble. Delivered end to end: service → router → `parseSse` → page.
**Verified:** `test_mid_stream_failure_emits_reset_before_the_fallback_restarts`,
`tutorGrounding.test.tsx`.

### F-4 · A configured fallback provider was ignored on the first failure

Found by a test written for F-3, not by inspection. Both `ask` and `ask_stream`
gated the fallback on `router.fallback_active`, which only flips inside
`select_provider` — so the turn that discovered the outage raised, and only
*subsequent* turns were served by the fallback. With `failure_threshold=3` that
is three user-visible 502s on a system with a working fallback.

**Fix:** the fallback is used as soon as the primary fails; the breaker still
spares later requests. Errors still propagate when no fallback is configured.
**Verified:** `test_circuit_breaker.py` updated to the corrected contract, plus a
new test that the error still propagates without a fallback.

### F-5 · A misspelled `ENV` silently disarmed every boot guard

`config.py:216` (pre-fix)

```python
return self.env.strip().lower() in PRODUCTION_ENVS   # {"production","prod","staging"}
```

`ENV=prodction`, `ENV=preview`, `ENV=live` — any unrecognized value was treated
as development, so the entire production guard was skipped and the service booted
with `jwt_secret="dev-insecure-change-me"`. `is_production` gates the JWT secret,
SMTP, CORS allowlist, PII key, metrics auth and Redis rate-limit checks, so this
was the root cause behind several other findings rather than an isolated bug.

**Fix:** inverted to a deny-list (`NON_PRODUCTION_ENVS`). Unrecognized means
production. The boot error now names the offending `ENV` and lists the values that
skip the checks.
**Verified:** `tests/test_env_gate.py` (8 tests), including that `ENV=ci` and
`ENV=test` still boot.

### F-6 · A role change did not revoke the target's sessions

`routers/admin.py:96` set `target.role` and committed. Outstanding tokens kept
authorizing against the new role until natural expiry, so demoting or suspending
a user had no immediate effect — precisely backwards for an urgent offboarding.

**Fix:** bumps `sessions_invalidated_at`, the same mechanism password change and
reset already use. Deliberately unconditional: making it depend on an actual role
delta would leave an offboarding path open to any caller sending back the role the
target already has.
**Verified:** `tests/test_access_and_spend_control.py` (14 tests).

### F-7 · Six provider-calling routes had no budget check and no rate limit

`check_ai_budget` was called only from the tutor routes. Question papers,
regenerate, replace, lesson plans, `/teacher/generate/{kind}`, chapter content and
`/teacher/jobs` each made a real provider call with no per-user ceiling and no
limiter rule. Because their usage was also never ledgered, `/admin/ai/quality`
reported a cost total that excluded them.

`/auth/register`, `/auth/join-school`, `/auth/change-password` and
`/parents/link/invite` were unthrottled — the first two are unauthenticated
endpoints for account creation and invite-code guessing.

**Fix:** `_require_ai_budget()` on every generation route; rate-limit rules added
for all of the above. Budget stays off when `AI_MONTHLY_BUDGET_USD_PER_USER <= 0`,
so default configuration is unchanged.

Registration is limited to 20/min per IP rather than something tighter: a school
onboarding staff shares one NAT egress address, so a 5/min cap would lock out a
legitimate onboarding session. Per-email throttling is the correct control for
this endpoint and is **not** implemented — see *Residual risks*.
**Verified:** `test_generation_routes_refuse_once_the_budget_is_spent` and
`test_generation_routes_remain_available_when_no_budget_is_set` over all four
routes.

### F-8 · `light_stem` never fired on any Bengali word

`retrieval/hybrid.py:20`

```python
_BANGLA_RE = re.compile(r"\u0980-\u09FF")     # no character-class brackets
```

This matched the literal three-character sequence `\u0980-\u09FF`, never Bengali
text. Consequences, all verified by execution:

- `light_stem("গাছগুলো")` returned `"গাছগুলো"` unchanged; the module docstring
  promised it would stem to `"গাছ"`.
- All 17 suffixes and all 16 `QUERY_EXPANSIONS` entries were unreachable for
  inflected input — the natural way a student types a question.
- Zero tests covered any of it.

The three sibling modules (`bm25`, `embedding`) had the correct bracket form,
which is how the inconsistency survived.

**Fix:** one-character change, plus `tests/test_bangla_stemming.py` (20 tests)
that pins every suffix, the minimum-length rule, longest-match ordering, and the
end-to-end property that an inflected form and its dictionary form now collide.
Recall@1 moved 0.38 → 0.39 and chapter-title Recall@1 0.225 → 0.2375 on the
committed corpus; Recall@5 for chapter titles moved 0.525 → 0.45, so the change
is a net recall improvement but not uniformly so.

### F-9 · An empty NCTB corpus silently served the sample textbook

`initialize/dependencies.py:166` (pre-fix)

```python
if settings.nctb_corpus_dir:
    chunks = load_nctb_corpus(...)
    if chunks:
        return chunks
return load_sample_corpus()      # ← silent
```

With `NCTB_CORPUS_DIR` set but empty, five bundled synthetic textbook files were
served under real chapter names with `content_type="text"`, while `/ready`
checked only the provider and the database and reported healthy.

**Fix:** when the variable is set it *is* the corpus; an empty one raises at
startup in production. Outside production the sample corpus is still used so the
suite runs without a corpus mount.

### F-10 · The committed retrieval metrics could not be regenerated

`scripts/evaluate_nctb_retrieval.py:112` called `tutor._grounded(question,
top_score, top_text)`. That method no longer exists; it raised `AttributeError`
on every run. The metrics in `data/nctb/retrieval_eval.json` were published as
MEASURED and could not be reproduced by their own tooling.

**Fix:** ported to `tutor._gate(question, gate_hits)` with the service's
`top_k`, since `_gate` accepts any one chunk that covers the question — scoring it
against `top_k=1` would have reported a better refusal rate than the service
actually achieves. Script now runs clean and the committed JSON was regenerated
from that run.
**Verified:** `tests/test_eval_harnesses.py` fails the build if the harness ever
references a method that does not exist.

### F-11 · `pip-audit` was red and CI gates on it

`pyjwt>=2.9` and `pypdf>=5.0` had no upper bound and no lockfile, so a fresh
install resolved to versions carrying 25 known advisories: 13 against PyJWT
(PYSEC-2026-41xx) and 8 against pypdf (PYSEC-2026-415x). The pypdf ones matter
most — that parser reads operator-supplied textbook PDFs.

**Fix:** floors raised to the first patched release of each advisory
(`pyjwt>=2.15.0`, `pypdf>=6.19.0`). A floor rather than a ceiling, so security
updates still flow. No code change; the vulnerable paths were unreachable by
accident of resolution, not by design.

**Verified:** `python -m pip_audit` → `No known vulnerabilities found`.

## Owner actions

These need repository-owner or GitHub-settings permissions:

1. **Rotate `VERCEL_OIDC_TOKEN`.** It was reachable by the web build context
   (`apps/web/.dockerignore` did not exist) and `release.yml` exported build
   stages to the Actions cache. Rotation is the only complete remediation.
2. **Confirm the Vercel Git integration is disabled.** `vercel.json` cannot
   express this; if it is on, Vercel builds every push independently of
   `vercel-deploy.yml` and the CI gate is not the only path to production.
3. **Configure branch protection** on `main` requiring `API CI`, and require it
   for tag creation so `release.yml` cannot be bypassed by pushing `v*` directly.
4. **Set `API_ORIGIN`** in the Vercel project (still outstanding from
   2026-10-06; the edge proxy answers 503 until it is set).
5. **Set `AI_MONTHLY_BUDGET_USD_PER_USER`** to a real ceiling per deployment.
6. **Provision Alertmanager** or accept that no alert is ever delivered.
7. Enable **Dependabot** (`github-actions` + ecosystems) before pinning actions
   by SHA.
